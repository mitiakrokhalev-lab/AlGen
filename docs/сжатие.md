# Сжатие выдачи: состояние и с чего продолжить

Ветка `claude/project-thread-x5hadw` (от ветки ускорения `claude/project-thread-e9ydwu`, влита до 6feb18f). Правила и их проверки — в `docs/класс-перебора.md`, раздел «Сжатие выдачи: правила».

## Что сделано

- `py/algen/compress.py` — сжатие внутри схемы под флагом `ALGEN_COMPRESS` (хук в `enumerate.run`). Ни одна строка не удаляется: добавляются «№», «свёрнута», «следует из». Жадный базис относительно теории; вопросы — гипотезы под селекторами; факты — базис без теории; `reopen` возвращает зависящие от опровергнутого; `verify` — независимая проверка на выборке; `regress` — сверка до/после; правила-экземпляры φ(t) по φ(G) с проверкой сорта, класса, гипотез базы и условий существования.
- `enumerate.generic_filter`: при `ALGEN_CLASS` снимает условие о терме, только если терм доказуемо в классе (дыра 4.11: на G∗G терялось 154 вопроса у finite и 126 у abelian; прогон 41770444167, вернулись ровно они). Влито в ветку ускорения (6feb18f).
- `py/algen/compress_base.py` — сжатие между схемами базы по каркасу (общая теория всех схем базы). Сводка схемы при сжатии содержит «оставленные вопросы».

## Что не проверено

1. **Сжатие между схемами** — код и тест есть, прогон `compress-base` (6 схем G + общий базис по каркасу G) запущен 4.11 ≈ 10:00 UTC, результат не разобран. Без него оценка «тысячи вопросов» не обоснована: внутри схемы остаются сотни, схем сотни тысяч.
2. **Другие базы** (G, N и прочие с несколькими переменными) — сжатие не запускалось. Экземпляры там идут через таблицу базы G (`form.generic`).
3. **Парные атомы** («P(A) и P(B)») не сворачиваются (оставляются) — дыры нет, но сжатие меньше.
4. **«Тот же класс» между схемами** у баз с симметриями переменных: `verify_across` принимает только буквально равные запреты; симметричные копии он пометит как нарушение — проверить на базе с двумя однородными переменными.
5. Ссылки «следует из» бывают длиной до ≈ 170: при опровержении одного вопроса возвращается много строк (без дыр). Укорачивание ядра почти не помогает (`TRIM_PASSES = 0`).

## С чего продолжить

1. Посмотреть итог workflow `compress-base` на этой ветке: «оставленных вопросов в схемах» против «оставлено» после сжатия между схемами и нарушения verify.
2. Встроить `compress_base` в сводку пилота (`batch сводка`) — после перебора каждой базы.
3. Прогнать `compress_run` на одной схеме базы G, N.

Запуск замеров на GitHub — пушем в эту ветку с «[compress-run]», «[compress-base]» или «[generic-diff]» в сообщении коммита.
