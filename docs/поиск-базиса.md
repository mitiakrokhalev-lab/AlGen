# Эскиз поиска следующего непокрытого вопроса

Непроверенный исследовательский проект, 7 ноября 2026. Не реализация и не замена текущего генератора. Провести малое полное сравнение до интеграции. Цель — обойти миллионы кандидатов до вызовов decide, вместо ускорения их цикла на проценты.

Фиксируем одну полную допустимую область атомов и термов, T — прежнюю теорию, E — частичные строки примеров. Кандидат p⇒g: выбираем до k литералов посылки и одну цель. Допустимость задаётся теми же req, ограничением s, покрытием переменных, типами, симметриями, непротиворечивостью литералов. Для прототипа не менять правила существующего класса и не сужать набор. Можно сначала взять маленькую схему без чисел и собрать область всех допустимых кандидатов явно для сравнения.

Предлагается SAT-решатель метауровня с селекторами P_i (посылки) и G_j (цель), cardinality(посылки)≤k/exactly-one(цель). В нём также копия переменных T: P_i⇒v_i, G_j⇒¬v_j. Модель T с выбранными посылками и ложной целью доказывает НЕВЫВОДИМОСТЬ, а не ложность в группах. Согласовать знаковую кодировку литералов i/i^1 с одним атомом v, нельзя дать независимые значения противоположным литералам.

Пример r опровергает p⇒g ровно когда все выбранные посылки имеют записанное true и отрицание цели имеет записанное true. Неопределённое значение посылки не считается истинным; неопределённая цель не считается ложной. Для строки вводим A_r⇔∨_{i:m[r,i]!=true}P_i; для каждой известной ложной цели j: G_j⇒A_r. Если выбранных посылок нет, A_r=false, так что правила для k=0 также верны. Клаузы OR должны иметь обе стороны эквивалентности; свободный A_r всё испортит.

Так мета-SAT ищет сразу неопровергнутое и невыводимое условие. Конкретный кандидат проверяется существующим decide и матрицей независимо; приводится к допустимой минимальной форме без потери req/покрытия. Порядок/ядра старого отчёта автоматически не сохраняются — это новый алгоритм построения базиса с полным сертификатом охвата, а не уже засчитанное побитовое ускорение старого report.

Следующий шаг: в поиск включаем совместимый с T набор пока нерешённых гипотез B, как при нынешнем сжатии. Копия T∧B с выбранными посылками и ложной целью ищет вопрос, не следующий из этого базиса. Сам B не объявляется теоремой: все связи означают условную свёртку, пока вопросы B не решены руками/примером/библиотекой. Добавление новой q в B разрешено только после проверки совместности T∧B∧q. Из несовместимых вопросов нельзя получать всё взрывом. Если q несовместима с B, она остаётся отдельным нерешённым вопросом и блокируется ровно её код кандидата (не всё дерево усилений). Это корректно, но в худшем случае таких вопросов много и ускорение исчезнет. Объединение разных совместимых базисов — отдельная задача.

Конечное UNSAT мета-поиска означает: каждый допустимый кандидат опровергнут примером, выведен теорией/допустимым базисом или уже явно сохранён как исключение. Для утверждения этого охвата нужны точное соответствие мета-кодировки классу и независимая проверка. Ошибка/timeout мета-SAT не означает полноту. Требования библиотеки к definedness, невозможным условиям и известным противоположным значениям также должны совпасть с текущим pipeline.

Размер кодировки: O(число строк × число литералов) ссылок даже с общими A_r, плюс T. Это может быть слишком велико; одинаковые проекции строк можно объединять для логической фильтрации, отдельно сохраняя индексы/веса/support. Нельзя переносить ожидаемый выигрыш до замера. При новой строке меняется мета-задача, при новом правиле нужен новый контекст/проверка зависимостей. Новый язык или s расширяет область.

План первого эксперимента: мини-область с неизвестными значениями, k=0..3, req и несовместимыми гипотезами. Перечислить все допустимые кандидаты старым способом; проверить каждую выдачу/свёртку и каждое окончательное UNSAT по всей области. Потом один малый настоящий Library/SAT-контроль. Лишь после этого думать о замене обхода полной native-схемы и пересчёте архива. Этот документ не является реализованным изменением генератора.

## Поправка после независимого review

Минимизация исходного кандидата c в q не позволяет блокировать только q: если q несовместима с B, meta может бесконечно возвращать старый c. Сохраняем исходную selector-проекцию c. Сохранённый отдельно q должен покрыть c с проверенной связью q⇒c (при удалении посылок без смены цели это тавтология); затем блокируется именно код c по селекторам P/G, а не одна модель переменных T. Либо c остаётся самостоятельным вопросом. Блокировка целой области усилений допустима только с отдельным сертификатом покрытия. Это обеспечивает прогресс по конечному пространству исходных кандидатов; блокировка только нормализованного q его не обеспечивает. Ошибка обнаружена review_live до реализации; эксперимент по-прежнему не выполнен.

Остальные обязательные границы review: связь q⇒c проверяется через T∧fixed∧q∧¬c БЕЗ несовместимого B, иначе получится ложное доказательство взрывом. Перед поиском проверяется SAT(T∧fixed). req кодируются через выбранные посылки/доказанные константы, а не случайно истинные v модели. Oracle первого эксперимента должен перечислять всю допустимую область, а не только минимальные ответы enumerate_form. После опровержения вопроса B удалять его и раскрывать все зависимые свёртки. Полнота и выигрыш ещё не установлены.
