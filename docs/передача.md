## 1. Цель

Дима (владелец репозитория) строит реестр нетривиальных фактов общей алгебры и топологии. Реестр состоит из трёх частей:

- словарь;
- базовые правила;
- архив того, что генератор не закрывает.

Генератор (`py/algen/enumerate.py`) перебирает условия вида «посылки ⇒ ¬цель» над схемой и делит их на четыре класса:

1. **выводится** из базы правил;
2. **опровергается** примером из библиотеки групп;
3. **опровергается примером с пометкой** («короткий довод» или «трудно»);
4. **остаток**: ни вывода, ни примера.

Остаток печатается строками «не бывает? …». Такая строка означает одно из двух: либо в базе не хватает правила (факт верен), либо в библиотеке не хватает примера (факт неверен).

Цель Димы, его словами: **«чтобы по 1000 очевидных фактов не выводились»**. Остаток на каждой схеме должен состоять только из настоящих вопросов, а не из очевидных пробелов в базе или библиотеке. Схем планируется около десяти, список в разделе 6.

Как работать с Димой:

- Пиши по-русски, коротко.
- Он доверяет: «Продолжай работу. Я тебе довольно доверяю, но если прям сомневаешься — спрашивай».
- Неуверенные теоремы не вноси молча. Спроси его или вноси только доказанные частные случаи со ссылкой.

Все Python-команды запускаются из `py/` (на машине нужен `pysat`):

```
cd py
python3 -m algen.library               # сверка библиотеки с базой: «противоречий 0» обязательно
python3 -m unittest discover -s tests  # тесты, должно быть OK
cd .. && node tools/dump-rules.mjs grp > /tmp/rules.json && cd py && python3 -m algen.check_rules /tmp/rules.json
                                        # проверка правил на конечных группах: не должно быть опровергнутых
```

Перебор на схеме идёт около 10 минут, поэтому вывод сохраняй в файл:

```
python3 -m algen.enumerate --посылок 2 --схема "∀ G : Grp" \
  --термы "center(G); commutator(G); G / center(G)" > out.txt 2> stats.txt
```

- Статистика пишется в stderr. Её первые строки: «запретов N: выводится …, неизвестно …», «кластеров: …».
- Без `--схема` используется основная форма G, N, G/N.
- Остальные флаги: `--подгрупп`, `--json`, `--короткие` (показать запреты с коротким доводом).

Чтобы удобно смотреть кластеры остатка, сожми вывод:

```
grep "^не бывает" out.txt | python3 -c "
import sys,re
for l in sys.stdin:
    m=re.match(r'не бывает\? (.*?)(?: & одно из: (.*?))?\s+\[запретов (\d+)(?:; заполнить (.*))?\]$', l.strip())
    if m: pre,opts,n,fill=m.groups(); print(n,'|',pre,'|',(opts or '')[:100],'|',(fill or '').split(', ')[0][:80])
"
```

## 4. Как устроен один проход

1. Запусти перебор и сожми вывод (раздел 2).
2. Для каждого крупного кластера реши, какой это случай.
   - **Подсказка «заполнить X у G = …».** В библиотеке не хватает значения. Впиши его с доводом в `почему`. Если значение выводится из других, убедись, что `saturate` его выводит.
   - **Факт верен.** Добавь правило в `data/new/grp.json`, массив `«добавить»`. Нужны `id`, `scene`, `if`, `then`, `доказательство`, `статус`, `ссылка`. Отрицание пишется как `"значение": false`. Термы: `{"op": "commutator", "args": ["X"]}`, `center`, `quotient`, `prod`. Правила о произведении `prod(X, Y)` пиши в двух вариантах, (X) и (Y), потому что произведение не коммутативно в теории.
   - **Факт неверен.** Добавь пример в `data/infinite/grp.json`. Шаблон — любая запись, например `UT4Z` или `DihQ`.
     - `свойства`: только то, что точно знаешь;
     - `почему`: довод на каждое нетривиальное значение;
     - `подгруппы`: всегда есть `"1"` и `"все"`; у нормальных указан `фактор`; `≅` — ключ существующей группы;
     - поля `центр` и `коммутант` — id подгрупп;
     - пометки `"трудно": [...]` и `"короткий довод": [...]` ставь для значений, которые держатся на теоремах.
3. После правок запусти `algen.library` (0 противоречий), `check_rules` и тесты. Потом перезапусти перебор и сравни остаток.
4. Закоммить. В сообщении укажи, как изменился остаток. В конце коммита — строка `Co-Authored-By` по правилам среды. Запушь в `rework/6-enum`.

## 5. Что важно знать о коде

- **Library.** Объект `py/algen/library.py:Library` содержит 1057 конечных групп из GAP и около 85 бесконечных из `data/infinite/grp.json`.
  - `_center_commutator` проставляет центр и коммутант по свойствам: у абелевой и совершенной группы, у простой и у группы без центра.
  - `saturate()` (новое) дописывает значения, выводимые по базе в сценах (G, N). Пометка ставится, если значение держится на помеченных. Вызывается в `enumerate.run` и в CLI перед `synthesize_products`.
  - `synthesize_products` строит около 4500 произведений A × B. Их центр и коммутант — пары подгрупп (Z(A) × Z(B), A′ × B′), с `maximal` и `finite-index`.
  - В базу произведений входят бесконечные группы, конечные порядка ⩽ 8, простые и `EXTRA_FINITE` (A₄, S₄, SL(2,3), SL(2,5)).
- **Ловушка с термами.** Не добавляй термы в `Scene.__init__` до построения `Theory(g, grow=1)`: `quotient(G, center(G))` раздувает теорию, и решатель зависает. Вместо этого формулируй правило через подгруппу N сцены, например «central(N) & simple(X/N)».
- **Ловушка с id.** Номера подгрупп конечных групп в произведениях пишутся с префиксом «№», иначе они путаются с «1 × B».
- **Цена правил.** Каждое правило должно доказываться в пару строк или иметь точную ссылку. `check_rules` проверяет правила на конечных группах, а бесконечные проверяет только `algen.library` через противоречия.
