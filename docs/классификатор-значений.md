Для запрета «посылки, фиксированный фон, отрицание цели»:

| Вид | Что известно по текущей таблице |
|---|---|
| A | Есть строка без ложных литералов, с одним неизвестным примитивным значением |
| B | Строки A нет; есть совместимая строка с двумя или более неизвестными |
| C | Каждую строку исключает известный ложный литерал запрета |
| R | Весь запрет известен истинным в некоторой строке: имеется опровержение |

R имеет приоритет над A/B: если опровержение уже есть, недостающие значения
других строк не делают условие ожидающим данных. События отдельных значений
у R могут сохраняться для диагностики; разреженные частоты включают только A.

Это характеристика данных, а не вердикт теории. Пустая библиотека даёт C,
не доказательство. Нужное значение кандидата A даёт контрпример;
противоположное исключает эту строку, а условие может остаться открытым.

Положительная пара раскрывается в знаковые примитивы; дубликаты, включая
fixed, считаются один раз. «¬P(H) и ¬P(K)» даёт две отрицательные составляющие.
Отрицание конъюнкции и несовместимый запрет явно отвергаются; эти входы
не возникают у допустимых минимальных условий действующего генератора.

Все события хранят (row,column), включая знак требуемого значения.
Для A считаются точные разреженные частоты; эвристическое value_name не
используется как идентификатор. Снимок битовой проекции свежий и неизменяемый:
Form._bits кэшируется по идентичности матрицы и мог бы устареть после правки
на месте. Исходные условия, поддержки и матрица не меняются.

SHA здесь описывает **числовую проекцию**, не заменяет архивный контекст.
При интеграции нужны отдельные привязки строк к подстановкам, столбцов к
атомам, версии таблицы и языка. Сливать схемы только по этому SHA нельзя.

пополам; непоместившееся одиночное условие оставляет явную ошибку/долг.
Усечённого «полного» результата нет. Память самой проекции и всего архива

## Что требуется для динамики

ValueBatch не является сохраняемой границей. В нём события отдельных значений
выдаются для A и диагностически для R; разреженные частоты относятся только
к A. B представлен числом совместимых строк,
а не полным списком недостающих значений. Хранение только событий A пропустит
переход B→A после заполнения первого значения. Нужны сохранённое условие и
индекс всех примитивных атомов его запрета, включая fixed и раскрытые пары.
По этому индексу изменённое значение выбирает затронутые условия; классификация
повторяется для них на новой проекции, без повторной генерации всей схемы.
Индекс охватывает все сохранённые A/B/C/R, включая известные литералы:
исправление ложного значения может изменить C, отзыв опровержения — R.
Это консервативный индекс правок ячеек фиксированной проекции: он может
выбрать лишнее, но не пропускает затронутое условие. Добавление строки требует
отдельного события и проверки всех сохранённых условий соответствующей
схемы на новой строке, даже если все её значения пока неизвестны.

Начальное точное имя наблюдения — (область схемы, конкретная подстановка строки,
примитивный атом). Номер строки и столбца имеет смысл только вместе с сохранённой
нумерацией, происхождением и поколением таблицы. Между схемами наблюдения
объединяются лишь по проверенному соответствию конкретных фактов. Эвристическое
value_name, совпадение числовой проекции или изоморфность абстрактных групп сами
по себе такого соответствия для всех отношений и подгрупп не дают.

Статусы данных A/B/C/R и статусы доказательства хранятся отдельно. A/B могут
быть уже доказаны; отложенный SAT оставляет явную очередь проверки. Новый факт
Library меняет классификацию данных; новая теорема может закрыть условие даже
без изменения данных. Исправление/отзыв факта и добавление новой строки должны
перепроверять соответствующие причины отсечения, а не только счётчики A.

Сохранение всех сегодняшних минимальных условий всё равно не покрывает
завтрашние минимальные условия. Новый контрпример слабому условию может открыть
его более сильное надусловие. Поэтому поток классификатора — один слой архива;
для обещания «не генерировать всю область заново» отдельно нужна полная явная
или символическая граница кандидатов с актуальными причинами покрытия.
Без неё завершение такого потока не закрывает долг полного архива.

Следующий законченный этап после контроля: версионированный журнал блоков
условий/классификаций, точные привязки атомов и строк, индекс зависимостей всех сохранённых A/B/C/R,
восстановление после сбоя. На малой полной области каждый переход после
добавления/исправления/отзыва данных сверяется с прямым пересчётом; отдельно
проверяется раскрытие ранее неминимальных надусловий через границу. Размер
журнала и индекса измеряется до большого запуска. Этот этап пока не реализован.
