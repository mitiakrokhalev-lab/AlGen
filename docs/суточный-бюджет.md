# Цель: полный зафиксированный план за сутки

7 ноября 2026. Дима уточнил цель: уложиться в24ч; ×100 не обязательное число.
Для пробной аренды допустимо до1000₽/сутки. Это бюджет подбора, не разрешение
оформлять заказ/платёж. Сейчас ничего не арендовано и не оплачено.

Точный текущий план42баз ещё не пересчитан. Старые130662схемы нельзя объявлять
актуальным охватом. Нужно получить manifest: версия языка/класса, список и
число схем каждой базы, hash плана. Неизвестный/недосчитанный объём не равен0.

Условный расчёт для130000схем (не прогноз проекта):

|---|---:|---:|
|20|1728000с|13,29с|
|40|3456000с|26,58с|

Из бюджета ещё вычитаются таблицы, инициализация, обновление архива, ошибки
и повторы. Cold (сборка входов) и warm (готовые входы) считаются отдельно;
один не выдаётся за другой. Распределение схем тяжёлое, поэтому один Ulm или
стресс-набор G не заменяет стратифицированный пилот нескольких баз.

Для оценки: W_cpu=сборка+сумма N_base×измеренная стоимость+ошибки/повторы.
Необходимая нижняя граница wall≥max(W_cpu/P_eff, самая длинная неделимая
задача). P_eff ограничен реально загруженными ядрами, памятью и квотами,
а не рекламным числом vCPU. Один нынешний процесс использует около одного
CPU; 20GitHub jobs не равны измеренным20или80занятым ядрам.

Измеренные memory peaks дают предварительный рабочий резерв8GiB на тяжёлый
процесс; не переносить его на все42базы без профиля. При подборе числа
процессов держать резерв системы и ограничиваться80% фактического лимита.
Общая immutable память при fork/mmap может разделяться, но выигрыш нужно
проверить по PSS/дереву процессов; сумма RSS не даёт его автоматически.
Текущее C++ ускорение увеличило пик одного большого числового контроля на
0,408GiB — это учтено, а не скрыто за коэффициентом времени.

Порядок действий: CI → сравнительный stress-02 → manifest42баз → пилот
нескольких баз с CPU/wall/PSS/диском → выбор числа работников и серверов.
До оценки полного W_cpu обещания «весь архив за сутки» нет.

Аренда ограничена41,67₽/ч в сумме при ровно24ч, включая диски/IP/трафик,
налоги и валютные расходы. Первый кандидат по форме — RAM-сбалансированный
почасовой CPU-сервер, а не GPU. Конкретные vCPU/GB выбираются по admission
памяти и пробному измерению; 64GB/8vCPU — лишь ориентир запроса цены.
