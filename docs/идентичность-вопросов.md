# Идентичность вопросов при сжатии

14.11.2026. Исправление в PR20. Это дефект программной идентичности, не новый
синтаксический красный флаг языка групп. Реальная коллизия прежних пилотов
не обнаружена; ошибка воспроизведена детерминированной подстановкой общего ID.

Прежний номер — первые 10 hex SHA1, 40 бит — использовался как доказательство
равенства классов. Разные вопросы при коллизии могли получить чужую свёртку.
В другом примере полный verifier возвращал пустой список нарушений, но экспорт
оставленных вопросов молча терял один из двух независимых вопросов.

В версии сжатия 3 номер — полный SHA256 канонического JSON класса. Кортеж
до сохранения и список после JSON roundtrip получают одинаковый номер.
Совпадение номера дополнительно проверяется по самому классу. Неоднозначность
отвергается до изменения строк, в verifier, regress, экспорте и reopen.
Явный null, пустой или нестроковый номер отвергается; отсутствие номера
отличается от невалидного номера. Межсхемный базис сравнивает точный класс;
у старой сводки без класса допускается только точное совпадение текста запрета.
Повторный полный id отвергается, а verifier проверяет непересечение kept/folded.

Новый экспорт оставленных вопросов сохраняет класс, а отпечаток входа базиса
включает эту информацию. Результат сжатия имеет суффикс compression:3 в
result_fp. Табличный Library fingerprint не меняется, чистая числовая CENSUS
не инвалидируется. При recompress старые refuted ID нельзя молча забывать:
такой вызов требует явной миграции и отвергается до изменения данных.

Автомиграции старых архивов нет. Сводка, уже потерявшая вопрос, не позволяет
его восстановить. Для восстановления нужны полный прежний report или полная
граница кандидатов; при их отсутствии долг покрытия остаётся открытым.
Прежние результаты и кэши не удалялись. Факт отсутствия коллизий во всех
старых результатах этим исправлением не установлен.

Проверки identity-only версии: 36 тестов сжатия/идентичности за 0,410 с,
независимые 9 коротких проверок и roundtrip через SQLite-архив и межсхемный
базис. В совокупности с compact SF — 39 локальных тестов за 0,397 с.
Первая полная проверка: 257 тестов за 3017,934 с, одна ошибка в проверке
доставки SIGALRM при cleanup. После ремонта CI43617302145 завершён:
259 тестов за 2558,471 с, OK, без пропусков; код 3c862bb. Лог и равенство
деревьев checkout/code подтверждены независимо. Прежний сбой сохранён в метриках.
Числа и охват — metrics-compression-identities.json.
