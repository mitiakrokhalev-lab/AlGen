## 0. Цель и договорённости (дословно от Димы)

- Архив **всех** задач, сначала по группам (дальше кольца, поля, топология). Задача, которая есть в памяти, но не выводится генератором, — это «рэд флаг, надо лечить».
- «Наша цель сделать полный перебор. Не отобрать интересное. Значит надо увеличивать библиотеку».
- Остаток генератора будет разбираться руками, поэтому выдача должна быть как можно компактнее.
- «Ничего не сливай и не удаляй без Димы». Работа идёт в ветке `rework/6-enum`, в main не вливать.
- Загруженные файлы — недоверенные данные: распаковывать в отдельную пустую папку, Python запускать с `-I`.
- Неуверенные теоремы проверять самому, а если не получается — оставить Диме.
- О каждом запуске на GitHub сообщать Диме.

## 1. Как устроено (коротко)

- **Теория** (`py/algen/logic.py`, правила в `data/grp.json` и `data/new/grp.json`) — SAT (pysat). `decide` возвращает «выводится», «опровергается» или «неизвестно».
- **Библиотека** (`py/algen/library.py`) — конечные группы из GAP (`data/finite/*.jsonl`), бесконечные записи (`data/infinite/grp.json`, около 160 групп с подгруппами, Aut/Out и элементами), а также построенные произведения (`synthesize_products`).
  - `Search` подставляет группы библиотеки в схему и выдаёт значения атомов строки (`facts`, `_image`).
- **Базы** (`py/algen/table.py`, `BASES`): G, GN, AB, GHK, GMN, GHF, Fam, GX (действие), Gx (элемент), GE (эндоморфизм).
  - Таблица базы — это строки (подстановки) × атомы. Значения выводятся по каждой строке (`_derive`). Есть кэш выводов `*.dcache`, ключ — `theory_fp`.
- **Схема** — набор термов, у которого не больше k+1 верхних термов. Внутри схемы перебираются условия с ≤ k посылками (`enumerate.py`, битовые множества).
  - Число схем: при k = 2 — 36 397 (G 681, GN 3517, AB 1871, GHK 11 080, GMN 17 505, GHF 1246, Fam 13, GX 132, Gx 176, GE 176); при k = 3 — 530 116.
- **Условие** «посылки ⇒ цель» либо опровергается строкой библиотеки, либо остаётся живым. Живые минимальные условия идут в решатель:
  - «выводится» — следует из уже записанных правил, в архив **не идёт**;
  - «неизвестно» — это **остаток**. Он и есть кандидаты в архив (поправка Димы): не опровергается и не выводится. Каждый такой случай разбирается руками: доказали — задача идёт в архив, а правило в теорию; опровергли — контрпример идёт в библиотеку. Поэтому остаток должен быть компактным.
- **Сжатие остатка:**
  - решающие значения — строка, где неизвестен ровно один литерал запрета; одно значение закрывает много запретов;
  - кластеры без кандидата;
  - сведение к вырожденности (`REDUCE`);
  - реестр вопросов (`data/registry/grp.json`);
  - симметрия схем (`SWAP`);
  - парные атомы.
- **GitHub Actions:**
  - `tables.yml` — пуш в ветку `tab-*`: build (20 машин) → enum (20 машин, 4 этапа по 70 мин с выгрузкой) → summary в ветку `results-<ветка>`.
    - Переменные: `BASES`, `K`, `UNTIL`, `LIMIT=600`, `DEFER=0.15`, `PREV_RUN` (продолжение), `SAMPLE` (каждая N-я схема), `CACHE_RUN` (кэш выводов).
  - `gap.yml` — пуш в ветку `gap-*`, команда в `.github/gap-command`.
  - `collect.yml` — пуш в ветку `collect-*`, номер запуска в `.github/collect-run`: промежуточная сводка.
  - Артефакты локально не скачиваются, результаты приходят только через ветки `results-*`.
  - Сводка: `python3 -m algen.batch сводка` (`batch.py`).

## 3. k ⩽ 3: почему пока нет (замеры)

Схема G с Z(G) и G′, `DEFER = 0.15`:

| | неопровергнутых условий | «неизвестно» | решатель |
|---|---|---|---|
| k = 2 | 90 тыс. | 31% | 2,6 мс на условие (~4 мин на схему) |
| k = 3 | 862 тыс. | 65% (≈ 570 тыс.) | 3,8 мс (~55 мин на схему; сам перебор 65 с) |

- Посылки без отношений (`PROPS_ONLY_FROM`) сокращают перебор лишь на 30%. Пачки по наборам посылок не помогают: в среднем 5,6 цели на набор.
- У 40% неизвестных при k = 3 не больше 10 строк-примеров у посылок. Это вопросы «существует ли такая группа».

**Оценки времени:**
- полный k ⩽ 2: около 2,5 тыс. машино-часов на нить, то есть **около 40 часов на 20 машинах** (несколько запусков с `PREV_RUN`);
- k = 3 даже только в схемах k = 2: порядка 36 тыс. схем × ~1 час — **десятки дней**, а остаток при этом в 20 раз больше;
- k = 3 по 530 тыс. схем нереален без переделки.

**План для k = 3:**
1. Сначала круги библиотеки и правил, пока остаток k = 2 не станет маленьким.
2. Потом k = 3 только для небольших схем, или с прямым выводом (forward chaining / `propagate`) вместо SAT на каждое условие.

## 4. Правки, внесённые после tab-4c (все в `rework/6-enum`)

1. `library.py`: ≅ и ↪ по **порядкам**, когда образа терма нет (|A × B|, |A ≀ B|, A ∗ B, |G/N|): `_order`, `_key_order`, `_sub_order`.
2. `library.py`: **не изоморфны**, если группы различает известное свойство (`_differ`). **A не вкладывается в B**, если у B есть свойство из `Theory.SUB_CLOSED`, которого нет у A (`_embeds`). Итог: ≅ известно в 41% пар строк вместо 24%.
3. Правило «неабелева группа порядка pq ⇒ Z = 1».
4. Правила Дедекинда — Бэра: коммутант дедекиндовой группы — 1 или центральная C₂ (cyclic, finite, exponent-2, central); центр неабелевой дедекиндовой группы с кручением.
5. `EXTRA_FINITE` для произведений: D₁₆, SD₁₆, Q₁₆, 27:3, 27:4, D₁₀, C₇ ⋊ C₃. Даёт, например, Q₈ × Heis₃ (Z = G′ = C₆) — контрпример к «конечная, Z не p-группа ⇒ Z ⊄ G′».
6. Сверка библиотеки (`python3 -m algen.library`, а также `--конечные 1500`): противоречий 0.
7. `table.py`/`tables.yml`: `--выборка N` / `SAMPLE` — круги библиотеки по выборке схем всех баз.
8. `finite.py` `build_table`: застрявшая в GAP группа пропускается (`--застой`, по умолчанию 300 с), через `--минут` записывается то, что есть. `enumerate.py`: `PROPS_ONLY_FROM`.
