# Как ещё сжать выдачу и время: идеи (4.11, не проверены)

Цель — базис вопросов, из которого (вместе с теорией и библиотекой) следует каждое утверждение класса. Ручной разбор идёт только по базису. Ниже — что может сократить базис и время. В скобках — насколько я в этом уверен.

## 1. Сжатие между схемами (есть код, не проверено)

`compress_base`: вопрос схемы S следует из вопросов других схем базы. Внутри одной схемы G, Z(G), G′ осталось 868 вопросов из 174 610; схем 130 тыс., и большинство вопросов в соседних схемах повторяют друг друга. Это первый замер после пилота 8 (уверенно: нужен).

## 2. Вопросы-схемы вместо вопросов-экземпляров (идея)

Сейчас «экземпляры» сворачивают φ(t) по φ(G). Обобщение: гипотеза — не одно утверждение, а схема по терму:
- «P наследуется конструкцией c»: P(G) ⇒ P(c(G)) для всех G (c — центр, коммутант, Aut, фактор…);
- «P переходит на подгруппу / фактор / расширение»;
- «R(t, c(t))» для отношения R.

Одна такая гипотеза закрывает вопрос во всех схемах, где встречается пара (P, c). Таких пар порядка (число свойств) × (число конструкций) ≈ 60 × 60 = 3 600, а экземпляров — сотни тысяч. При ручном разборе это ровно то, что человек и решает: «наследуется ли хопфовость центром?» — один вопрос, а не сто.

Реализация: в сжатие добавить кандидатов-схемы. Строка сворачивается, если следует из теории, оставленных вопросов и схемы-гипотезы, не опровергнутой библиотекой. Проверка честная: схема — тоже вопрос, её опровержение возвращает строки (как reopen). (Уверенность средняя: сильно зависит от того, сколько вопросов на самом деле имеют такой вид — проверить на выдаче пилота 8.)

## 3. Поиск примеров по требованию (идея, сильная)

Вопрос «P ⇒ Q?» почти всегда жив, потому что в библиотеке нет примера P ∧ ¬Q. Для конечных групп пример часто есть среди SmallGroups порядка ⩽ 2000. Нужно не строить для них всю таблицу, а:
- по оставшимся вопросам собрать нужные свойства;
- в GAP найти группу (или пару (G, N), подгруппу…) с P ∧ ¬Q;
- добавить её в библиотеку.

Для бесконечных — перебор построений из библиотеки: A × B, A ≀ C₂, свободные произведения, фактор по известной нормальной подгруппе.

Каждый найденный пример убивает все вопросы, которые на нём держатся (решающие значения это уже показывают). Это автоматический «круг библиотеки». (Уверенно: по прошлым прогонам большая часть остатка — дыры библиотеки, а не открытая математика.)

## 4. Вопросы о существовании вместо импликаций

Если посылки P выполнены у ⩽ нескольких групп библиотеки, все цели при этих посылках — один вопрос «какие группы бывают с P» (сводка уже так группирует). В базис брать сам вопрос «существует ли группа с P ∧ ¬Q» по классам равносильности целей. (Есть частично.)

## 5. Время

- Подсказки (решающие значения, вопросы, кандидаты) считать только для строк, оставшихся после сжатия: около ×1,5 (замер из status).
- Анализ формальных понятий: перебирать только замкнутые множества посылок (замыкание по строкам таблицы). Наборы посылок с одинаковым замыканием дают одинаковые условия (идея из `СОСТОЯНИЕ.md`, раздел 10).
- Каркас: память — транзитивность ⩽ на достроенных подгруппах (status, дыра 2).

## Потолок ручного разбора (оценка, не замер)

Аккуратный разбор вопроса — найти пример или доказательство со ссылкой. По опыту кругов библиотеки это минуты–часы на вопрос, в среднем, скажем, 20–50 вопросов в день вдвоём с машиной.
- За 2–3 месяца это 2–4 тыс. вопросов.
- Значит, цель для всего класса — **не больше 2–3 тыс. вопросов в базисе после автоматического поиска примеров**, а лучше около 1 тыс.
- Сейчас без сжатия между схемами это сотни на схему × 130 тыс. схем — на три-четыре порядка больше. Пункты 1–3 должны дать эти порядки; проверять по пилоту 8.
