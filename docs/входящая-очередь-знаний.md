# Надёжная входящая очередь: контракт следующего шага

15.11.2026. Проект протокола, **ещё не реализован и не проверен сбоями**.
Точка опоры — экспериментальный RowKnowledge из PR22. План не закрывает
ни один gate полного запуска и не меняет класс генератора.

## Идентичность и задания

Долговечное задание содержит точный контекст языка/схемы/Library/Theory,
конкретную подстановку, структурный атом либо неизменяемый пакет источника,
тип намерения и внешний ключ события. Хэш служит индексом; при совпадении
сравнивается точное содержимое. Один внешний ключ с другим содержимым — ошибка.
Для наблюдения значение, желаемая полярность и версия источника не входят
в его идентичность. Несколько вопросов могут ждать одного вычисления значения.

Намерения: вывести примитивное наблюдение, зарегистрировать проверенный
пакет/новую версию, отозвать конкретную версию, явно восстановить версию.
Один объект источника имеет собственный порядок намерений: старое сообщение
не должно случайно восстановить уже отозванный пакет. Строковое имя версии
не задаёт этот порядок; явный возврат старой версии является новым намерением.

Первый worker ограничен уже зарегистрированной строкой и неизменным Theory.
Смена языка/правил, добавление строки, отсутствующая конструкция и миграция
контекста остаются отдельными заданиями с явным долгом. Если пакет не имеет
математической проверки, он не становится доверенным благодаря метаданным.
Эксперимент с пакетами предположений должен иметь явный режим и сохранять
долг первичного происхождения.

## Доставка, попытка и подтверждение

Входящее намерение сохраняется до ответа вызывающему коду. Worker создаёт
долговечную **попытку**: уникальный внутренний event key, точный нормализованный
payload и ожидаемую ревизию журнала. Только после сохранения попытки вызывается
RowKnowledge. Его packet включает expected_revision: повтор с другим номером
под прежним ключом не является допустимым retry.

После неизвестного результата worker сначала повторяет **тот же packet**.
Существующий rk_event возвращает прежний receipt до проверки текущей ревизии.
Подтверждение, что коммит не состоялся, позволяет завершить старую попытку
причиной stale. До новой попытки заново проверяются порядок и актуальность
самого намерения, затем читается текущая ревизия. Устаревший put_source не
должен воскресить пакет после более нового withdraw: для superseded сохраняется
причина без вызова RowKnowledge. Явное restore — отдельное новое намерение.
Нельзя молча переписать payload/ревизию старой попытки.

Успех намерения записывается только после подтверждённого коммита строки.
Доставка допускает повтор; идемпотентность обеспечивается сохранённым ключом
попытки и точным packet. Заявлять распределённое exactly-once здесь нельзя.
Результат undetermined завершает попытку вычисления, но сохраняет недостающее
знание и долг доказательства соответствующих условий. В текущем API это
успешный коммит события с новой ревизией даже без нового значения. Следующая
попытка берёт receipt.ledger.revision либо более свежую прочитанную ревизию;
трактовать undetermined как откат к прежнему номеру нельзя.

При нескольких worker нужен последовательный исполнитель для одного журнала
и ограждение прежнего владельца. Одной истекающей аренды недостаточно: старый
worker может продолжать работу после назначения нового. Первая реализация
должна запрещать одновременный запуск писателей; многопроцессный протокол с
fencing-token требует отдельной проверки. Правило одного тяжёлого локального
процесса сохраняется.

## Хранилища и архив

SAT-подготовка может держать транзакцию RowKnowledge достаточно долго, чтобы
заблокировать запись входящего события в ту же SQLite. Раздельная очередь —
кандидат для проверки. Для двух файлов нельзя предполагать общий атомарный
коммит: между журналом и подтверждением очереди остаётся окно сбоя. Оно
закрывается сохранённой попыткой и повтором точного события, а не обещанием
транзакции между независимыми базами.

Для последующего подключения архива нужен outbox, записываемый в транзакции
со строкой: ревизия, точный контекст, изменённые наблюдения/затронутые коды,
основания и версии источников. Доставка в архив повторяема; подтверждение
outbox требует проверки конкретного импортированного поколения. Это ещё
одна очередь и отдельный следующий этап, существующий RowKnowledge её не пишет.

Подтверждённое изменение строки не закрывает enumerate/compress долги
LiveArchive. Все сохранённые A/B/C/R пересчитываются по изменённым примитивам,
но исходные поддержки не становятся актуальными автоматически. Старые
минимальные коды не покрывают все будущие сильные условия: полная явная либо
символическая граница остаётся обязательным отдельным блокером.

## Проверки до подключения

| Точка остановки | Ожидаемое восстановление |
|---|---|
| До сохранения попытки | Намерение остаётся pending |
| После сохранения попытки, до вызова | Повторяется сохранённый packet |
| В середине source/proof/row транзакции | SQLite откатывает поколение; повтор той же попытки |
| После коммита строки, до подтверждения очереди | Точный retry получает прежний receipt |
| После подтверждения очереди, до доставки outbox | Архивный outbox остаётся pending |
| Не совпали язык/Theory/схема | blocked migration и явный долг, без подмены контекста |
| Пришла старая версия намерения | Сохраняется проверяемая причина, порядок не нарушается |
| Не хватает бюджета или источник противоречив | Прежнее поколение цело; событие и ошибка сохраняются |

Тест должен аварийно завершать настоящий дочерний процесс в этих окнах,
проверять таблицы, ревизии, источники, доказательства и все сохранённые коды
по внешнему оракулу после reopen. Одних mock-исключений недостаточно.
История намерений, попыток и причин не удаляется для получения красивой
статистики. Время, CPU, RSS, main/journal/TEMP/очередь/outbox и стоимость
неуспешных попыток измеряются отдельно. Пройденные тяжёлые пилоты без новой
причины не повторяются.
