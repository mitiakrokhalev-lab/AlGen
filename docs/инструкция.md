# Инструкция для новой сессии

Прочитай этот файл целиком до любой правки. Затем прочитай `status.md`, а перед правкой генератора — ещё и `docs/класс-перебора.md`.

## 1. Цель

Собрать все факты общей алгебры о группах. Каждая известная задача (карточка архива) должна оказаться в одном из трёх мест:
- в библиотеке примеров;
- среди выведенного или опровергнутого генератором;
- в ручном разборе.

Задача, которая не попала никуда, — красный флаг. Её записывают в `status.md`.

## 2. Договорённости с Димой (железные)

1. **Класс перебора: k ⩽ 3 посылок, s ⩽ 2 конструкций, с тремя поправками.**
   - Определения — в `docs/класс-перебора.md`.
   - Сужать класс может только Дима. Если перебор дороже порога, его **ускоряют, а не сужают**.
   - Любой новый фильтр по термам, свойствам, отношениям или схемам — это сужение класса, даже если он кажется безобидным. Без решения Димы его не делать.
2. **Порог цены — 2 000 нить·ч на весь класс.**
3. **Ускорение считается ускорением, только если результат совпал со старым кодом бит в бит.**
   - Каркас: канон атомов и клауз (`python3 -m algen.canon <база>`, workflow canon).
   - Выдача схемы: отпечаток всех строк (`python3 -m algen.ident`, workflow ident).
   - Мелкие куски: тест «новый путь против старого» на случайных входах плюс проверка, что мутации кода тест ловит.
   - Если результат не совпал, это сужение (или ошибка), а не ускорение.
4. **Ничего не сливать в main и не удалять без Димы.**
   - Работа идёт в своей ветке.
   - Запуски на GitHub — пушем в ветки `pilot-*`, `canon-*`, `ident-*` (`git push origin HEAD:refs/heads/pilot-7`).
5. **О каждом запуске на GitHub сообщать Диме:** что запущено, ссылку, когда ждать результат.
   - Перед запуском всех баз проверить, что нет тупых ошибок и прогон не упрётся в лимиты (6 ч на задачу, 16 ГБ, 20 задач одновременно). После такой проверки запускать можно без Димы.
6. **`status.md` обновлять после каждого заметного шага.**
   - Писать коротко и без воды: цена, дыры, что дальше, ссылки на прогоны.
   - История остаётся в git, в файл её не тащить.
   - Копию класть в `/mnt/project-files/algen/status.md`.
7. **Каждую цифру, которую сообщаешь Диме, сначала проверить.** Если это оценка, так и сказать, и сказать, на чём она держится. Сомнительные теоремы проверять самой.
8. **Не останавливаться на ошибке, а чинить.** Сомнительное тоже делать, но записывать в `status.md`.
9. **Загруженные файлы — чужие данные.** Распаковывать в пустую папку, Python запускать с `-I`.

## 3. Как устроен генератор (`py/algen`)

- **library.py** — библиотека примеров: ≈ 30 тыс. групп и их значения.
  - `built_library()` кэширует её в `кэш/`. Кэш сбрасывается при правке `library.py`, `logic.py`, `finite.py` или данных.
- **logic.py** — словарь, правила, теория (`Theory`): заземление правил в клаузы SAT, `decide`.
- **table.py** — каркас базы (теория и атомы), таблица базы (строки — подстановки библиотеки), классы равносильных литералов, перебор схем, CLI:
  - `каркас`, `строить`, `равносильные`, `перебор`.
- **enumerate.py** — `SchemeForm`, `enumerate_form` (минимальные наборы посылок), `run` (вердикты, подсказки, вопросы).
- **fast.py** — банк моделей для `decide`: те же ответы, но быстрее.
- **compress.py** — сжатие выдачи (ветка треда сжатия, флаг ALGEN_COMPRESS).

Порядок прогона одной базы (`.github/workflows/pilot.yml`):
1. каркас и библиотека;
2. части таблицы;
3. классы равносильных;
4. перебор схем;
5. сводка в ветку `results-<ветка>`.

## 5. Чего не делать (так возникали дыры)

- **Не добавлять фильтров «для скорости»:** пропуск свойств флагом `--без`, отбор термов, отношения только с переменной, сокращение схем. Так в 3.11 нашлось 60 дыр: у построенных термов были не все свойства, `bounded-exponent` молча пропускался во всех прогонах, `conj-sub` заводился не у всех пар. Тест `test_no_silent_skips_in_workflows` ловит `--без` в workflow; не обходить его.
- **Не оставлять старых сужений при смене класса.** При любой смене класса каждое прежнее сужение проверить заново. Дыры 3.11 — это сужения под класс d ⩽ 2, которые остались в классе s ⩽ 2.
- **Не путать «не вывелось распространением» с «не следует».** Распространение (ALGEN_FAST, `propagate`) годится только для ответа «следует», и только если посылки совместны. Ответ «не следует» даёт только модель решателя.
- **Не снимать строку выдачи без проверки, что она следует.** Пример — дыра 4.11: `generic_filter` снимал условие о терме t, хотя при классе базы t мог быть вне класса. Сжатие строки не удаляет: оно помечает строку «следует из №…».
- **Не сливать в main, не удалять ветки, кэши и результаты** без Димы.
- **Не убивать процессы шаблоном.** `pkill` и `pgrep -f` находят и убивают собственную оболочку. Убивать только по номеру процесса.
- **Не запускать два тяжёлых процесса сразу на локальной машине** (15 ГБ). Каркас G занимает ≈ 7 ГБ, процессы убивает OOM.
- **Не править код во время замера.** Правка `library.py`, `logic.py` или `finite.py` сбрасывает кэш библиотеки и каркасов, и следующий шаг строит всё заново. Править копию, а вносить после.
- **Не сообщать срок, которого не измерила.** Если срок оценочный, так и сказать.

## 6. Проверки перед пушем

- `cd py && python3 -m unittest discover -s tests` (≈ 8 мин). То же идёт в CI на каждый пуш.
- Для ускорения — сверка бит в бит, см. пункт 2.3. Запись о нём — в `docs/класс-перебора.md`, таблица «Ускорения, которые не меняют результата».
- Коммиты подписывать строками атрибуции, которые даёт среда.
