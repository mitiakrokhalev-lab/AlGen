# Схема данных AlGen

Документ описывает, как устроены данные генератора. Всё остальное — движок,
страница, фильтры — следует из него. Если что-то нельзя выразить в этой схеме,
менять надо схему, а не обходить её кодом.

Три решения, принятые до первой строчки кода (2026-09-19, по ответам
пользователя): кросс-категорные конструкции, элементный слой и семейства
объектов закладываются в схему **сразу**, хотя задачи по ним появятся позже.
Дописать их потом значило бы переделать хранение.

---

## 1. Сорта

Всё, что участвует в условии задачи, — это **терм**, и у каждого терма есть
**сорт**. Сорт записывается как `Категория.вид`:

| Сорт | Что это | Примеры термов |
|---|---|---|
| `Grp.obj` | группа | `G`, `G/N`, `G ∗ H`, `Aut(G)` |
| `Grp.sub` | подгруппа **данной** группы | `N ⊆ G`, `Z(G)`, `ker φ` |
| `Grp.mor` | гомоморфизм | `φ: G → H` |
| `Grp.elt` | элемент группы | `g ∈ G` |
| `Grp.fam` | семейство групп | `(G_i)_{i∈I}` |
| `Grp.act` | действие группы на группе | нужно для `N ⋊ Q` |
| `Ring.obj`, `Ring.ideal`, `Ring.mor` | кольца *(сделаны)* | `R[x]`, `√I`, `R/I`, `N(R)` |
| `Ring.elt`, `Ring.fam` | элементы и семейства колец *(зарезервированы)* | |
| `Fld.obj`, `Fld.mor`, `Fld.num` | поля *(сделаны)*; расширение L/K — это `Fld.mor` | `K̄`, `K(x)`, `[L : K]`, `Gal(L/K)` |
| `Mod.obj`, `Mod.mor`, `Mod.sub`, `Mod.elt`, `Mod.fam` | модули | `M ⊗_R N`, `M*` |
| `Top.obj`, `Top.sub`, `Top.mor`, `Top.pt`, `Top.fam` | пространства | `X/A`, `ΣX`, `βX` |
| `Set.obj` | множество | база свободного объекта, индексы семейства |

**Подсорта.** Запись `Grp.sub ≤ Grp.obj` означает: где ждут группу, можно
подставить подгруппу — речь пойдёт о ней как об объекте. Благодаря этому
«подгруппа `N` абелева» пишется просто `abelian(N)`, а не через отдельную
операцию «тело подгруппы». Свойства, осмысленные **только** для подгруппы
(нормальность, максимальность, характеристичность; для пространств —
замкнутость, плотность), объявляются на сорте `sub` и на объект не переносятся.

Это же решает старую путаницу: `normal(N)` — свойство **вложения**,
`abelian(N)` — свойство **тела**. Два разных сорта, одна запись.

Аналогично задумывалось `Ring.ideal ≤ Mod.obj` — идеал кольца есть модуль над
ним, и это кросс-категорное подсортовое отношение дало бы задачи бесплатно.
**Не сделано, и осознанно**: в разделе колец у `Ring.ideal` надсорта нет вовсе.
Идеал — не кольцо (единицы в нём нет), и подсорт `Ring.obj` тут был бы прямой
ложью: в выдачу полезло бы «верно ли, что идеал I — поле». А подсорт `Mod.obj`
требует, чтобы модульная модель умела считать идеал модулем, — а она умеет лишь
то, что действует через ℤ. Кольцом идеал становится через фактор `R/I`, и это
единственный переход, который язык разрешает.

**Зависимые сорта.** У терма сорта `Mod.obj` есть роль-кольцо: модуль всегда
над чем-то. У `Grp.sub` — объемлющий объект. Эти связи **не хранятся полем**, а
вычисляются из аргументов конструкции (см. `ambient`, `dom`, `cod`, `base` в
§3). Одно место истины вместо двух.

## 2. Категории

Файл категории объявляет: сорта, подсортовые отношения, свойства, конструкции,
теоремы, примеры, вырождения. Категории связаны двумя способами:

* **Вложение.** `CRing ⊂ Ring` — полная подкатегория. Теоремы и примеры
  объемлющей категории действуют в подкатегории; обратно — нет.

  Задумано было завести `CRing` отдельной категорией; **сделано иначе**, и это
  стоит записать. Коммутативность живёт свойством `comm` на `Ring.obj`, а
  теоремы, верные только в коммутативном случае, несут её посылкой: «`comm R`,
  `maximal-ideal I` ⇒ `field R/I`». Причина не в лени: отдельная категория
  раздвоила бы и базу, и библиотеку — ℤ пришлось бы объявить дважды, и сверщик
  проверял бы две копии вместо одной. Цена решения тоже понятна: конструкции,
  осмысленные лишь при коммутативности (радикал идеала, нильрадикал), частичны
  и требуют `comm` слотом — ровно как `torsion` требует `abelian` у групп.
* **Кросс-категорная конструкция.** Обычная конструкция, у которой сорт выхода
  из другой категории: `units: Ring.obj → Grp.obj`, `pi1: Top.pt → Grp.obj`,
  `spec: CRing.obj → Top.obj`, `groupRing: Ring.obj × Grp.obj → Ring.obj`,
  `free: Set.obj → Grp.obj`, `end: Mod.obj → Ring.obj`.

Никакого особого механизма для кросс-категорности не нужно — достаточно того,
что сорт входа и сорт выхода независимы. Ради этого сорта и сделаны строками с
префиксом категории.

## 3. Конструкции

Конструкция — это **операция над термами**, узел графа условия.

```json
{
  "id": "quotient",
  "name": "фактор",
  "in": [
    { "role": "X", "sort": "Grp.obj" },
    { "role": "N", "sort": "Grp.sub", "ambient": "X", "requires": ["normal"] }
  ],
  "out": "Grp.obj",
  "text": "%X/%N",
  "фраза": "фактор %X по %N",
  "commutative": false
}
```

Поля слота:

* `sort` — сорт аргумента (с учётом подсортов);
* `ambient` / `dom` / `cod` / `base` — **согласование**: слот `N` обязан быть
  подобъектом именно того терма, что стоит в слоте `X`. Для `Grp.mor` это `dom`
  и `cod`, для `Mod.obj` — `base` (общее кольцо);
* `requires` — свойства, без которых операция **не определена**. Это и есть
  частичность: фактор кольца берётся по идеалу, а не по подкольцу; в полях
  собственных факторов нет вовсе. Частичность — не досадное ограничение, а
  первый фильтр: граф, в котором `requires` не выполнено, не является задачей.

Флаг `commutative: true` (произведение, копроизведение, свободное
произведение) говорит канонизатору, что аргументы можно сортировать.

### Виды конструкций

**Вводящие (нульарные по объектам).**

| id | что |
|---|---|
| `given` | «пусть `G` — группа со свойствами …» — свободный вход сцены |
| `named` | конкретный объект из библиотеки: `ℤ`, `S₃`, `Q₈` |
| `presented` | ⟨ образующие ∣ соотношения ⟩ *(сорт зарезервирован, разбор позже)* |
| `formula` | объект, заданный формулой первого порядка *(зарезервировано)* |

**Выбирающие** — вносят в условие новый объект с наложенными свойствами;
это операции 5 и 6 из постановки:

| id | вход → выход |
|---|---|
| `choose-sub` | `obj → sub` |
| `choose-mor` | `obj, obj → mor` |
| `choose-elt` | `obj → elt` |
| `choose-fam` | `Set.obj → fam` |

У выбирающего узла есть **квантор**: `∃` (условие вводит такой объект) или `∀`
(утверждение обо всех таких). По умолчанию `∃`.

> Ловушка, стоившая прошлому проекту задачи: отрицание `∀`-узла ставится
> **перед** «всякая»: «не всякая подгруппа `G` делима», а не «всякая подгруппа
> `G` не делима». Движок выводит `¬∀`, и текст обязан утверждать `¬∀`.

**Универсальные** (есть в каждой достаточно полной категории, имя и смысл
меняются): `prod`, `coprod`, `pullback`, `pushout`, `equalizer`, `coequalizer`,
`ker`, `im`, `coker`, `limit`, `colimit`, `initial`, `terminal`.

> Пушаут — одна операция на три пункта постановки: в `Grp` над тривиальной
> подгруппой это свободное произведение, над нетривиальной — амальгама
> `G ∗_H K`; в `Top` — склейка `X ∪_f Y`; в `CRing` — `R ⊗_A S`. Объявляется
> один раз, работает везде.

**Канонические подобъекты** — выбора нет, берётся именно этот: `center`,
`commutator`, `frattini`, `fitting`, `socle`, `sylow`, `torsion`, `radical`,
`nilradical`, `annihilator`, `centralizer`, `normalizer`, `closure`,
`interior`, `boundary`.

**Обратные к фактору** — то, чего не было в постановке: `extension` (даны `N` и
`Q`, взять `E` с `N ◁ E`, `E/N ≅ Q`), `semidirect`, `central-extension`, `hnn`,
`wreath`.

## 4. Вырождения

```json
{ "op": "quotient", "when": { "N": { "trivial": true } }, "equals": "X",
  "почему": "G/1 ≅ G" }

{ "op": "ker", "when": { "F": { "injective": true } },
  "equals": { "op": "trivial-sub", "args": ["dom F"] },
  "почему": "ядро вложения тривиально" }

{ "op": "quotient", "pattern": { "N": { "op": "commutator", "args": ["X"] } },
  "equals": { "op": "ab", "args": ["X"] },
  "почему": "G/[G,G] — это абелианизация" }
```

`when` — условие на свойства аргумента, `pattern` — на его строение. `equals`
либо имя роли, либо конструкция над ролями и их связями (`dom F`).

Список равенств термов, которые надо применять **до** всего остального. Служит
сразу трём целям:

1. **Дедупликация.** Без неё одна задача выдаётся десятками пересказов. В
   численном слое прошлого проекта это дало 135 000 «находок» против 1500 после
   приведения к канонической форме — и здесь будет хуже, потому что
   конструкции вкладываются.
2. **Отсев вырожденных условий.** `G/1 ≅ G`, `G/G ≅ 1`, `ker` мономорфизма
   тривиально, `im` эпиморфизма — вся группа, `G × 1 ≅ G`, пуллбэк над
   терминальным объектом — произведение.
3. **Тождества-сокращения**: `G/[G,G]` — это абелианизация;
   `(G/N)/(M/N) ≅ G/M`; подгруппа подгруппы — подгруппа.

Вырождение с условием (`ker φ` тривиально, **если** `φ` инъективен) применяется
только когда условие **доказано** из посылок — иначе мы потеряем задачу.

## 5. Свойства

```json
{ "id": "abelian", "sort": "Grp.obj", "name": "абелева",
  "фраза": "%s абелева", "отрицание": "%s не абелева" }
```

Свойство живёт **на сорте**. `normal` — на `Grp.sub`, `injective` — на
`Grp.mor`, `order-n` — на `Grp.elt`. Благодаря подсортам свойство объекта
автоматически применимо к подобъекту.

Позже здесь появятся: параметрические свойства (`exponent = n`), численные
(`|G| = n`, `rank`), и свойства, заданные формулой первого порядка.

## 5а. Отношения

Второй вид атома наряду со свойством — **двуместный**:

```json
{ "id": "le", "имя": "содержится в", "in": ["Grp.sub", "Grp.sub"],
  "same": "ambient", "формула": "%1 ⩽ %2" }
```

`same` требует совпадения согласующей связи: сравнивать можно подгруппы одной
и той же группы, а не любые две.

Отношения понадобились не из общих соображений, а по задачнику: `⩽` между
подгруппами стоит в посылке или цели у задач 5.10, 5.12, 5.14, 6.15, 6.16, а
`≅` — у 3.24, 3.55, 6.10, 7.10, 7.11 и у всех трёх теорем об изоморфизме.
Свойствами одного терма это не записывается вовсе.

Объявлены три: `iso` (изоморфизм объектов), `le` (включение подгрупп),
`eq-sub` (равенство подгрупп — не то же, что изоморфизм их как групп).

## 6. Теоремы

Клаузы Хорна над **сценой** — набором ролей с объявленными связями:

```json
{
  "scene": { "X": "Grp.obj", "N": { "sort": "Grp.sub", "ambient": "X" } },
  "if":   [ { "p": "abelian", "t": "X" } ],
  "then": { "p": "normal", "t": "N" },
  "ссылка": "подгруппа абелевой группы нормальна"
}
```

*(Раздел объявлен, но ещё не реализован: слой вывода — следующий шаг.)*

Термы в теореме — **образцы**: роль, либо конструкция над ролями (`Z(X)`,
`X/N`). Сопоставление образца с термом задачи и есть шаг вывода.

**Таблица сохранения** — теоремы особой формы, записываемые компактно внутри
конструкции:

```json
"preserves": ["abelian", "finite", { "p": "noetherian", "ссылка": "Гильберт" }],
"reflects":  ["nontrivial"],
"breaks":    [ { "p": "simple", "свидетель": "Z/4" } ]
```

`preserves` — свойство входа переносится на выход; `reflects` — наоборот.
Отдельно от них поле `gives` — то, что верно по самому построению и ни от чего
не зависит: ядро нормально, центр абелев, свободная группа без кручения.
Клетка, которой нет ни в одном из трёх списков, — **дыра**, и она печатается
как задача, а не как строка отчёта.

> Урок, который повторится в каждом новом разделе: длинное доказательство
> очевидного факта означает дыру в таблице сохранения, а не находку. Первые
> прогоны читать именно на это.

## 7. Библиотека примеров — это МОДЕЛЬ, а не список

Список объектов со свойствами умеет опровергать только утверждения про сам
объект. А условие задачи — граф построения, и опровергать надо утверждение про
построенный терм: «`G/N` циклична», «`Z(G × H)` тривиален». Поэтому библиотека
устроена как модель, в которой каждая конструкция языка **вычисляется**.

```json
{ "id": "S3", "имя": "S₃", "рецепт": { "вид": "перестановки", "генераторы": [...] },
  "порядок": 6, "props": { "abelian": false, "solvable": true, "simple": false } }
```

В данных лежат **рецепты**, а не таблицы умножения: таблица A₅ — это 3600
чисел, и хранить её незачем, когда она строится за миллисекунду. Свойства в
данных тоже есть, но не как источник истины, а как сверка при загрузке.

**Взаимная проверка дороже самих данных.** Правила базы писались раньше и
независимо; `tools/compute-groups.mjs` проверяет каждое из них на каждой
посчитанной группе и на каждой её подгруппе. Ноль расхождений означает, что
данные и код не разошлись, — и то же сравнение идёт при каждом поиске: если
база доказала, а пример опроверг, перебор сообщает о споре громче, чем о любой
находке.

**Бесконечные группы объявляются, а не вычисляются.** Второй сорт примеров
(`data/infinite.json`): у объекта записаны свойства, представительные
подгруппы, факторы по ним и результаты канонических конструкций.

```json
{ "id": "Z", "имя": "ℤ", "бесконечная": true,
  "props": { "cyclic": true, "finite": false, "free": true, … },
  "подгруппы": [ { "id": "2Z", "имя": "2ℤ", "объект": "Z", "props": { "normal": true, … } } ],
  "конструкции": { "center": "все", "commutator": "0", "aut": "C2" },
  "факторы": { "2Z": "C2", "0": "Z", "все": "C1" } }
```

Ссылка `объект` говорит, какой группе изоморфна подгруппа, — и свойства берутся
оттуда, а поверх кладутся свойства самого ВЛОЖЕНИЯ. Чего в записи нет, то
невычислимо, и строка примера просто не строится: выдумывать нельзя.

Поскольку всё это написано рукой, оно проверяется теми же правилами базы —
`tools/check-infinite.mjs`. Плюс проверки самой записи: фактор берётся только по
нормальной подгруппе, подгруппа «вся» обязана иметь те же свойства, что сам
объект, характеристическая обязана быть нормальной.

**Границы модели названы вслух.** Свойство, ОБЪЯВЛЕННОЕ одинаковым у всех
примеров библиотеки, — её слепое пятно: цель с таким свойством проверять нечем,
и это пишется в пометке. Считается это по каталогу, а не по столбцу таблицы:
постоянный столбец бывает постоянным и потому, что утверждение — теорема, а это
совсем другое дело. Смешивать «опровержения не нашлось» и «искать было негде»
нельзя.

**Таблица строится один раз на схему.** Привязка конкретных групп к свободным
вершинам не зависит от того, какие свойства мы потом навесим, — свойства только
отсеивают строки. Поэтому получается таблица «привязка × атом», проверка набора
посылок — фильтр по строкам, а проверка цели — взгляд в столбец. У цели есть
ЗНАК: «`G/Z(G)` не циклична» подтверждается строкой, где свойство ложно.

Доля подходящих примеров, на которых цель верна, отличает содержательное
опровержение от очевидного: ноль при многих подходящих — «ложно всюду», и такая
задача скучна; 95 % и выше — «тонкий контрпример», и её надо поднять наверх.

## 8. Граф условия

Задача — это пара «граф условия + цель».

**Граф** — DAG термов: вводящие узлы в листьях, конструкции выше, у выбирающих
узлов — наложенные свойства. Требования к графу, проверяемые до всякого вывода:

1. **Связность.** Все роли условия соединяются через узлы, имеющие входы. В
   прошлом проекте несвязных «утверждений» было 30 312 против 34 настоящих при
   одной посылке — это не фильтр, это ядро.
2. **Согласование.** Каждый слот удовлетворяет `ambient`/`dom`/`cod`/`base`.
3. **Определённость.** `requires` каждого слота выводится из посылок.
4. **Непустота.** Существует объект (или пример из библиотеки), удовлетворяющий
   условию. Если ни одного — утверждение пусто-истинно, и об этом надо сказать
   вслух, а не молча отбросить.
5. **Каноничность.** Граф приведён вырождениями к нормальной форме и не
   изоморфен уже выданному (канонизация с учётом симметрии коммутативных
   операций и взаимозаменяемых `given`-узлов).

**Квантор у вершины.** У выбирающего узла есть `quant`:

* `forall` (по умолчанию) — «пусть `N` ⩽ `G`», то есть утверждение про ЛЮБУЮ
  такую вершину. Контрпример — одна неудачная `N`. Так же рассуждает и вывод:
  он говорит о произвольном терме, а это и есть всеобщность;
* `exists` — «существует ли `N` ⩽ `G`, для которой …». Контрпример — целый
  объект, для которого подходящей `N` не нашлось. Свойства такой вершины
  уезжают внутрь вопроса, а не в условие.

Разница не косметическая. Вывод вперёд по клаузам Хорна доказывает только
«для всякого», поэтому для цели, задевающей `∃`-вершину, **база молчит**:
«всякая тривиальная подгруппа абелева» ничего не говорит о том, ЕСТЬ ли
тривиальная подгруппа. Отвечают тогда только примеры, и подтверждение на всех
примерах помечается вслух как подтверждение, а не как доказательство.

**Про какие вершины спрашиваем.** Поле `цели` ограничивает перебор целями про
названные вершины; пустой список значит «про все». У цели-отношения (`≅`, `⩽`,
`=`) в списке должны стоять ОБЕ вершины — иначе такая цель не рассматривается.

**Цель** — одна из:

* `P(t)` — терм графа обладает свойством (с `значение: false` — не обладает);
* `R(t, s)` — отношение из §5а: `t ≅ s`, `t ⩽ s`, `t = s`;
* `вычислить(t)` — «найдите …» *(ответ не выводится, а хранится; см. §9)*;
* численная цель *(зарезервировано)*.

Посылки бывают тех же видов и, кроме того, накладываются прямо на выбирающий
узел (`choose-sub` со свойством `normal`). Разница только в удобстве записи.

## 8а. Реестр мишеней

`data/targets.json` — задачи, которые генератор ОБЯЗАН находить, с источником
и статусом у каждой. Статусы: `выразима`, `нужно` (с точным перечнем
недостающего), `позже` (объявленный, но не сделанный слой), `встроена`
(выражена устройством схемы, а не задачей), `не наша`.

Договор проверяется `tools/targets.mjs` и тестом: всё объявленное выразимым
обязано собираться движком, иначе ненулевой код возврата. Когда появится
перебор, договор усилится до «обязано находиться».

Реестр — это и план работ: раздел «нужно» перечисляет ровно то, чего не хватает
базе, и каждый пункт оттуда стоит дороже любой догадки о том, что «наверное,
пригодится».

## 9. Корзины выдачи

Каждая пара «граф × цель» обязана попасть **ровно в одну** корзину, и сумма
корзин обязана сойтись с числом пар. Молчащий `continue` в переборе — это
потерянные задачи.

| Корзина | Что значит |
|---|---|
| `выводится` | доказывается из базы; глубина вывода — мера учебности |
| `опровергается` | есть пример библиотеки, где посылки верны, а цель нет |
| `пробел` | не выводится и не опровергается — **самое ценное** |
| `вырождено` | граф свернулся вырождениями |
| `несвязно` | условие распадается |
| `не определено` | `requires` слота не выполнено |
| `пусто` | посылки противоречивы |
| `повтор` | канонически совпало с уже выданным |

Скучное **прячется, а не выбрасывается**: у каждой пометки своя кнопка. Решение,
что показывать, принимает человек; задача генератора — назвать вслух, что с
задачей не так.

Отдельные пометки содержательности: `ложно-всюду` (цель ложна у всех подходящих
примеров, их ≥ 5) и `тонкий-контрпример` (цель верна у ≥ 80 % подходящих) —
вторые поднимаются в выдаче.

## 10. Чего здесь пока нет

Перечислено, чтобы не забыть и чтобы место в схеме было зарезервировано:

* задание объекта образующими и соотношениями (`presented`) — мишень 8.8;
* ПАРАМЕТРИЗОВАННЫЕ СЕМЕЙСТВА в библиотеке (Cₙ для всех n сразу, а не 34
  конечные группы поимённо). Без них цель «вычислить» — а она уже сделана —
  умеет только константу, определённую условием, и на мишени 6.4 и 8.4
  («найти порядок Aut(Cₙ)») ответа не даёт: там просят формулу от параметра;
* свойство, заданное формулой первого порядка (`formula`);
* `Ext`, `Tor`, производные функторы;
* точные последовательности и фильтрации как форма диаграммы.

Сделано с тех пор, как список писался: численный слой (порядки, индексы,
делимость — сорт `Grp.num`), пределы и копределы по направленной системе
(`lim`, `colim` над сортом `diag`), синтез произведений групп, РАЗДЕЛ КОЛЕЦ
(сорта `Ring.obj`, `Ring.ideal`, `Ring.mor`, кросс-категорные `units` и `add`
в группы, синтез произведений колец) и РАЗДЕЛ ПОЛЕЙ (`Fld.obj`, `Fld.mor` —
расширение есть вложение, — `Fld.num` для степени и кросс-категорная `gal`
в группы: Gal(ℚ(∛2, ζ₃)/ℚ) — это S₃ из каталога групп), ГРУППОВОЕ КОЛЬЦО
`R[G]` со свойством «без делителей нуля» (только с ним выражается гипотеза
Капланского), ЛОКАЛИЗАЦИЯ `R_p` и АЛГЕБРЫ над кольцом.

Алгебры сделаны БЕЗ отдельной категории, и это решение: алгебра над K — это
кольцо A вместе со структурным морфизмом K → A, образ которого лежит в центре.
Сорт `Ring.mor` уже есть, согласование dom/cod работает, библиотека колец
готова — вторая категория заставила бы объявить M₂(ℚ) дважды и сверять две
копии. Ровно так же расширение полей сделано морфизмом, а не отдельным сортом.

Цель «ВЫЧИСЛИТЬ» тоже сделана — как ОТДЕЛЬНАЯ форма вопроса, а не корзина:
корзины раскладывают пары «посылки × утверждение», и договор о балансе держится
на том, что каждая пара попала ровно в одну. Ответов на мишени 6.4 и 8.4 она
пока не даёт: там просят ФОРМУЛУ от параметра (|Aut(Cₙ)| = φ(n)), а наша форма
умеет только константу, определённую условием. Нужны параметризованные
семейства в библиотеке.
